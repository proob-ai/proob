# Benchmark results: proob v0.2.2

The bug sets were not rerun for v0.2.2. The latest full measurement is still [v0.1.0-rc1](v0.1.0-rc1.md) (18 of 20 held-out trials, 9 of 10 post-cutoff bugs, no wrong `Holds` in 260 scored verdicts); read its numbers as v0.1.0's, not this release's.

v0.2.2 ships the changes listed under v0.2.2 in [CHANGELOG.md](../../CHANGELOG.md): a project below the repository root can be named with `--project`, and `proob shadow open` sets up the Python environment itself.

## What was verified instead

| Change since v0.2.1 | How it was verified |
|---|---|
| `--project <language>:<dir>` on `proob init` and `proob shadow open` | New integration tests, in CI; locally, a monorepo fixture with a Python service in a subdirectory, and a shadow left by the v0.2.1 binary that gains the named project in its config and workflows. |
| `proob shadow open` sets up the Python environment | Unit tests for the order of interpreters, the stamp, and the refusal behind a link, in CI. Locally, on that fixture with `python3` at 3.10 and uv on `PATH`: one `open` made a Python 3.12 environment and five property checks then ran with no manual step; a commit that adds a requirement kept and refilled the environment; a requirement that cannot install was reported once and not tried again; with no uv and only Python 3.10, `open` exits 0 with one line of reason. |
| The reason for a missing Python tool on a Python older than 3.11 | Unit tests, in CI. |

## Not yet true

- The bug sets have not been measured on this release, including the effect of reserving `Holds` for proofs and models.
- The Python environment is set up only in a shadow, not for `proob init` in a checkout, and only on macOS was it run end to end.
- No team outside this repository has used proob yet.
