# Benchmark results: proob v0.1.0-rc1

The rerun after the first improvement cycle. Method: [`bench/README.md`](../README.md). Run on 2026-10-29. Kept small on purpose: 2 trials per held-out v1 bug, 1 per bug set v2 bug, 1 per Rust target.

| Setting | Value |
|---|---|
| proob | binary built from master `4c4f849` |
| Changes since v0.0.1 | interface laws stated by sense and declare (`c464ef4`); Python src-layout import fix (`a9ef57f`); untraced mutmut runs reported as not scored (`32a93fc`); sampled, parallel mutation scoring and tests-first `/proob:try` (`4c4f849`); soundness gate (`4e99d98`) |
| Agent model | `claude-opus-5-5`, Claude Code 2.1.312, web tools disabled |
| Tools | as v0.0.1; mutation scoring samples 30 mutants per property by default |

## Measure 1: real bugs detected (held-out only)

Nothing here was used for tuning. Bug set v2 holds bugs fixed after the model's training cutoff (June 2026), so a catch there cannot come from memory.

| Set | Trials that caught the bug | 95% Wilson | Bugs caught at least once |
|---|---|---|---|
| v1 held-out half (5 bugs, 2 trials each) | 9 of 10 | 60% to 98% | 5 of 5 |
| v2, fixed after the model's cutoff (10 bugs, 1 trial each) | 9 of 10 | 60% to 98% | 9 of 10 |
| **All held-out** | **18 of 20, 90%** | **70% to 97%** | **14 of 15** |
| v0.0.1, v1 held-out half, for comparison | 12 of 15, 80% | 55% to 93% | 5 of 5 |

| v1 held-out bug | v0.0.1 | rc1 |
|---|---|---|
| tomlkit | 3/3 | 2/2 |
| cachetools | 3/3 | 1/2 |
| packaging | 2/3 | 2/2 |
| unicode-segmentation | 2/3 | 2/2 |
| toml | 2/3 | 2/2 |

The v2 bugs: more-itertools, boltons, cattrs, tomlkit, portion, funcy (Python); bytes, ordered-float, rust_decimal, time (Rust). The one miss, `time`, is an adapter gap, not a reasoning miss: its tests compile only with `--all-features`, and the Rust adapter cannot pass cargo features yet, so every check errored.

Control: every credited catch was replayed twice on the buggy code and twice on the fixed code with its own seed: 24 of 24 stable. 22 of them joined the regression corpus; two unicode-segmentation catches could not, because the agent wrote those tests inside the source file the fix replaces.

Cost: median $1.75 per trial, about 6 minutes.

## Measure 3: verdict soundness

From `cargo xtask sim` and `cargo xtask bench soundness`: 260 verdicts over 240 generated worlds (approval × evidence × strength × code that holds or has a planted bug) and 20 scripted steps.

| Cell | Points | Count |
|---|---|---|
| correct Holds | +2 | 3 |
| correct Broken | +1 | 14 |
| other | 0 | 243 |
| wrong Broken | −16 | 0 |
| **wrong Holds** | −32 | **0** |

Score +20 of a possible 128; no unsound `Holds`. The gap to the maximum is proob abstaining (for example, a failing check on a property nobody approved reads `Not checked`, not `Broken`). Details: [`soundness-v1.md`](soundness-v1.md).

## Target repositories, Rust (speed)

| Target | v1 | rc1 |
|---|---|---|
| indexmap | 123 min, 2 of 5 properties scored | **9.4 min**, 5 of 5 scored, 4 able to fail, median kill ratio 0.18 of the sample, 0 failures, zero footprint, $1.72 |
| vaultwarden | killed by the disk guard at 27 min | **16.8 min**, 5 of 5 bound, 2 failures (triaged: 1 false alarm, 1 extreme-input-only; [details](../data/v0.1.0-rc1/vaultwarden-triage.json)), zero footprint, $1.71; **no scores**: the disk filled during scoring |

One indexmap property scored by itself: 700 s before, 66 s now (30 of 196 mutants sampled, 6 parallel jobs). With the cap lifted, parallel jobs alone reproduce the old counts exactly.

**Known defect:** the parallel-jobs rule assumes 1.5 GB of disk per job. vaultwarden needs about 2 GB per build copy, so 6 jobs filled the remaining disk and every score failed with an honest error. The next iteration sizes jobs from the measured size of the baseline build.

## Regression corpus

84 entries (catches and live findings), replayed with no model: 84 ok, 190 s.

## Threats to validity

- Small samples: 20 held-out trials; the interval is wide.
- One machine, low on disk; the vaultwarden scores are missing for that reason.
- The v2 "other failures" are not triaged yet, so no false-alarm rate is claimed for the bug sets in this release. The two vaultwarden failures were triaged: a path test that expected `/.` back where `/` is the same directory (false alarm), and a JSON key rewrite that drops one of two keys differing only in first-letter case (real behaviour, but only on input no Bitwarden client sends).
- Soundness ground truth for correct-code worlds follows proob's documented conditions for `Holds`; it is independent of proob's code only for the planted-bug worlds.
