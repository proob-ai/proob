# Benchmark results: proob v0.0.1

Method: [`bench/README.md`](../README.md). Bug set: [`bench/bugs.json`](../bugs.json), version 1 (11 bugs). Raw data: [`bench/data/v0.0.1/`](../data/v0.0.1/). Run on 2026-10-29.

| Setting | Value |
|---|---|
| proob | binary built from master `8160897` (before v0.0.1) |
| Agent model | `claude-opus-5-5`, Claude Code 2.1.312, web tools disabled |
| Trials | 3 per bug, 33 in total |
| Python tools | pytest 9.1.1, Hypothesis 6.169.4, mutmut 3.8.0, Python 3.13 |
| Rust tools | Rust 1.99.1, cargo-nextest 0.9.150, proptest 1.12 |
| Machine | macOS arm64, 3 trials in parallel |

## Measure 1: real bugs detected

The agent ran `/proob:sense`, `/proob:declare`, and `/proob:falsify` on each library at its buggy commit, in a fresh history that does not contain the fix. A trial counts only if one of its bound checks fails at the buggy commit and passes, with the same seed, once the developers' fix is applied.

| Library | Language | Difficulty | Trials that caught the bug |
|---|---|---|---|
| more-itertools | Python | medium | 3 / 3 |
| tomlkit | Python | easy | 3 / 3 |
| humanize | Python | medium | 3 / 3 |
| cachetools | Python | hard | 3 / 3 |
| python-semver | Python | easy | 2 / 3 |
| packaging | Python | medium | 2 / 3 |
| bidict | Python | easy | 0 / 3 |
| chrono | Rust | easy | 1 / 3 |
| unicode-segmentation | Rust | hard | 2 / 3 |
| rust-url | Rust | hard | 1 / 3 |
| toml | Rust | medium | 2 / 3 |

**22 of 33 trials caught the bug: 67%, 95% Wilson interval 50% to 80%.** 10 of the 11 bugs were caught in at least one trial.

Control: every credited catch was replayed twice on the buggy code and twice on the fixed code with its own seed. All 26 credited checks failed both times on the buggy code and passed both times on the fix. No credit came from a flaky check.

Cost and time per trial, for the whole agent flow: median 7.0 minutes and $1.85 (33 trials, $62 in total). Some trials sat idle for several minutes after finishing, waiting on a stray background search for the binary; that idle time is included and is a known harness and skill defect, so wall time is an upper bound.

## Measure 2: time to bug

For each caught bug, its first credited check was rerun with 30 fresh random seeds on the buggy code. Times are wall time of one `proob run check`, including the test runner's startup.

| Library | Seeds that found it | Median time | 95% CI |
|---|---|---|---|
| more-itertools | 30 / 30 | 2.9 s | 2.6 to 3.5 s |
| tomlkit | 30 / 30 | 8.3 s | 5.0 to 12.0 s |
| humanize | 10 / 30 | 1.0 s | 1.0 to 1.1 s |
| cachetools | 30 / 30 | 0.7 s | 0.7 to 0.7 s |
| python-semver | 30 / 30 | 3.2 s | 3.0 to 3.5 s |

Median times count only seeds that found the bug. The found-rate column is the other half of the answer: the humanize check finds its narrow input band with a third of seeds at the default budget of 256 cases. Cases to first failure are not reported yet, because the adapters do not record them.

## Measure 3: verdict soundness

Not scored in this release. Scoring `Holds` needs approval facts from GitHub; `cargo xtask sim` now produces them locally, and the next release scores every benchmark property with the SV-COMP scheme.

What can be said now is how often a counterexample was wrong. Every counterexample the checks produced that was not credited to the target bug (18 of 44) was classified against the library's documentation and its latest release ([`other-failures.json`](../data/v0.0.1/other-failures.json)):

| Class | Count |
|---|---|
| Real bug, still present in the latest release | 9 |
| Real bug, fixed upstream after the benchmark commit | 4 |
| False alarm: the agent's test was wrong | 5 |

**5 false alarms among 44 counterexamples: 89% of reported failures were real bugs.** The 9 live findings are five distinct bugs in current releases of python-semver (equal versions hash differently), rust-url (two: a slicing panic, and `set_ip_host` breaking the URL's invariants), and tomlkit (two: whitespace lost after a date, an emptied table printing as nothing).

## Threats to validity

- **Training-data exposure.** All 11 fixes date from 2025 and 2026, within the agent model's training window. The model may have seen some fixes. Bug set version 2 adds bugs fixed after the model's cutoff.
- **Small set.** 11 bugs, 3 trials each. The interval on measure 1 is wide on purpose.
- **Difficulty labels** were assigned by the person who selected the bugs, before any trial ran.
- **One harness defect** was found and fixed after the trials, before scoring: replays initially ran without the trial's Python environment. All Python trials were re-judged; no trial was rerun.
