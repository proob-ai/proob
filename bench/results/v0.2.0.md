# Benchmark results: proob v0.2.0

The bug sets were not rerun for v0.2.0. The latest full measurement is still [v0.1.0-rc1](v0.1.0-rc1.md) (18 of 20 held-out trials, 9 of 10 post-cutoff bugs, no wrong `Holds` in 260 scored verdicts); read its numbers as v0.1.0's, not this release's.

v0.2.0 is released mainly so that every archive carries a signed GitHub build record: v0.1.0 had none, and the launcher refuses an archive without one whenever `gh` is logged in. It also ships everything listed under v0.2.0 in [CHANGELOG.md](../../CHANGELOG.md).

## What was verified instead

| Change since v0.1.0 | How it was verified |
|---|---|
| `Holds` only for a proof or a model | Unit and integration tests in CI. |
| Kani adapter (pinned 0.68.0) and TLA+ adapter (pinned TLC 1.7.4) | CI runs real Kani and real TLC routes on fixtures. |
| `proob doctor`, `/proob:setup`, and installing tools into proob's own environment and directory | CI tests; locally, a Python environment with no pytest of its own and a Rust check with the tools only in `~/.proob/tools/rust/bin`. |
| `/proob:try` fails loudly, and the shadow report ranks failures by severity | CI tests; `/proob:try` on two outside repositories (a Python service, and a Go and TypeScript repository proob cannot check, which now stops with that reason). |

## Not yet true

- The bug sets have not been measured on this release, including the effect of reserving `Holds` for proofs and models.
- No team outside this repository has used proob yet.
